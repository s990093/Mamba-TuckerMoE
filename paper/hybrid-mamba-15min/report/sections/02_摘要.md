## 摘要（Abstract）

大型語言模型（LLM）在規模擴張的同時，長序列自迴歸推論面臨三大瓶頸：(1) self-attention 的時間成本隨序列長度呈平方成長；(2) KV Cache 隨解碼步數線性佔用統一記憶體；(3) 標準 Mixture-of-Experts（MoE）的專家權重總量高達 Dense 模型的 $E$ 倍，在消費級裝置上根本無法常駐。

本報告提出 **Hybrid Mamba-TuckerMoE**：以 Mamba-3 Selective SSM 為主幹、Grouped-Query Attention Transformer 為週期性全域回看層，並將所有前饋層替換為以 **Tucker 三階張量分解**共享輸入/輸出子空間的 **TuckerMoE**。TuckerMoE 讓 8 個 expert 共享 $U^{(2)}, U^{(3)}$ 因子矩陣，僅保留低秩 per-expert core $\mathcal{G}_e \in \mathbb{R}^{r_1\times r_2\times r_3}$——在 deployed checkpoint 上實現 **82.87% 參數壓縮**（2.4B dense-equivalent → 417M），且與同參數預算的逐專家 SVD 相比，重建 MSE 低 **45.3%**（0.00135 vs 0.00247）。

**訓練**方面，本研究採三階段遞進訓練策略，在 9.9 B tokens 上將驗證困惑度從 Pre-train（FineWeb-Edu）Val PPL **24.6** 降至 SFT（UltraChat 200k）**18.3**，再降至 CoT-SFT（自訂推理資料集）**12.1**，整體下降 **50.8%**。

**推論**方面，本研究在 Apple MLX 上實作 TPU-style **StaticDecoder**：以 `mx.compile` 將 embed → 24 Mamba Block → 6 GQA Block → head → sampling 編譯為**單一計算圖**（~50 dispatch → 1），搭配兩個自訂 Metal kernel（`fused_ssm_step` 融合 ~20 個 MLX ops；`fused_tucker_gw` 融合路由鏈），再加選擇性 8-bit 量化 TuckerMoE 因子矩陣，將 M2 Pro decode 吞吐從 **47 tok/s 提升至 135–144 tok/s**。

**加速解碼**方面，本研究提出**多策略推測 Jacobi 解碼（SJD）**：三來源草稿系統（運行時 N-gram Cache、SuffixRetriever、Phase-Aware CoT Cache）並行驗證 $K$ 個候選 token，無須 draft model 即可在 $K=16$、2048 tok cold 設定下達到 **3.12× end-to-end 加速比**（Demo 場景 **3.20×**），輸出正確性在 greedy decode 下嚴格保證。

**記憶體**方面，TuckerMoE 模型在 M2 Pro bf16 下的峰值解碼記憶體從 512 context 的 **1.2 GB** 到 32K context 的 **3.1 GB**，而等效 Dense FFN（2.4B）在 32K 時 OOM（>16 GB）。

核心命題：**在相同算力預算下，以 TuckerMoE 擴增容量可獲得與更大 Dense 模型同等級的生成能力，同時將邊際專家成本壓低至 Standard MoE 的 $1/800{,}000$，使 2.4B 容量的模型真正可部署於 Apple Silicon 消費級裝置。**
