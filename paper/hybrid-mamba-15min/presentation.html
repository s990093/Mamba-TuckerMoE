§1 · Transformer 的雙重規模瓶頸

Self-attention 在自迴歸推論中同時面臨時間與記憶體的平方級成長。

⏱️ 時間複雜度瓶頸
\[\sum_{t=1}^{N} O(t \cdot d) = O(N^2 d)\]
  • 每步生成需計算與所有先前 token 的注意力
  • 累計成本呈平方成長
  • 長序列推論成為部署瓶頸
💾 KV Cache 記憶體爆炸
\[\text{KV mem} \propto L \times N \times d_h \times H_{\text{kv}}\]
  • 每層每 1K token ≈ 1.5 MiB
  • 30 層 × 32K 上下文 → 記憶體消耗驚人
  • 裝置端部署幾乎不可能
核心問題：兩個瓶頸共同使「裝置端長上下文推論」成為 LLM 落地的主要阻礙。

§1.2–1.3 · 兩條獨立的演化路徑

學界分別從「時間複雜度」與「模型容量」兩個方向突破瓶頸。

🔄 路徑 A：SSM 取代 Attention
\[h_t = \bar{A}_t h_{t-1} + \bar{B}_t x_t, \quad y_t = C_t h_t\]
  • 解碼記憶體 \(O(1)\)，與序列長度無關
  • Mamba：選擇式記憶，input-dependent \(\Delta, B, C\)
  • 弱點：精確全域查表不如 Attention
🧩 路徑 B：MoE 擴增 FFN 容量
\[y = \sum_{e \in \mathcal{E}(x)} p_e(x) \cdot W_e \cdot x\]
  • 每 token active FLOPs 與 dense FFN 相當
  • \(E\) 個專家 → \(E\) 倍模型容量
  • 代價：權重儲存 \(E\) 倍，記憶體壓力巨大
本研究：結合兩條路徑 → Hybrid Mamba-3 + TuckerMoE

§5.2 · Mamba-3 Selective State Space Model

固定大小的隱藏狀態 \(h \in \mathbb{R}^{n \times p}\) 壓縮式記憶所有歷史資訊。

SSM 核心遞迴方程
\[h_t = \bar{A}_t h_{t-1} + \bar{B}_t x_t, \qquad y_t = C_t h_t\]

\(\bar{A}=\exp(\Delta A)\) — input-dependent 選擇性記憶，\(\Delta\) 控制遺忘/保留

🔑 關鍵特性
  • Complex-valued RoPE — 相對位置敏感性
  • MIMO rank=4 — 4 個獨立 SSM head
  • Chunk-Parallel Scan — \(O(\log N)\) 深度
  • TuckerMoE × 2 — in_proj + out_proj
⚡ 結合律保證平行化
\[(a_i,b_i) \bullet (a_j,b_j) = (a_ja_i, \; a_jb_i+b_j)\]

chunk 內平行前綴和，chunk 間 carry 合併 — 兼顧速度與記憶體。

Chunk-Parallel Scan 結合律運算示意
圖：利用結合律 \((a_i,b_i) \bullet (a_j,b_j)\) 將序列掃描平行化為 \(O(\log N)\) 深度的 prefix sum — 訓練時 chunk 內平行計算，chunk 間透過 carry state 合併

§5.4.1–5.4.3 · MoE 痛點與 Tucker 分解

Top-K MoE 的兩大核心痛點，以及 Tucker 分解如何系統性解決。

💥 痛點 1：路由崩塌
  • 馬太效應 — 少數「明星專家」吸走大多數 token
  • Load-Balance Loss 與語言建模目標存在干擾梯度
  • 解決：\(\mathcal{L}_{\text{LB}} + \mathcal{L}_{\text{Z}}\) + 溫度退火
🐌 痛點 2：Memory-Bound 推論
  • Decode 時每位 expert 僅 ~4 token → 算術強度 ≈ 4
  • 遠低於 H100 BF16 平衡點 (~400 FLOPs/Byte)
  • 完整 \(d_{\text{in}} \times d_{\text{out}}\) 權重需全部載入 HBM
逐專家 SVD（Baseline）
\[W^{(e)} = U^{(e)}_r \Sigma^{(e)}_r V^{(e)\top}_r\]

✗ 獨立分解，無法捕捉跨專家冗餘。60% 壓縮下 PPL: 7 → 7168

Tucker 三階分解（Ours）
\[\mathcal{W} \approx \mathcal{G} \times_1 U^{(1)} \times_2 U^{(2)} \times_3 U^{(3)}\]

✓ \(U^{(2)}, U^{(3)}\) 跨專家共享 → 82.87% 壓縮

Tucker 分解：能量分佈與核心張量稀疏結構
左：Tucker Core Energy Retention — 跨專家冗餘可視化，80% 資訊集中於少數核心成分。右：Expert Sparse Gate Matrix — 各專家身分向量的稀疏結構
