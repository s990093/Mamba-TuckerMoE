## 二、資料型別與快取策略

- **權重 dtype**：載入時根據 `--dtype` 轉換，預設 `bf16`。MLX 的 `mx.bfloat16` 在 M2+ 上效能與精度平衡最佳。
- **KV cache dtype**：若設為 `auto`，則採用與主權重相同的 dtype；亦可強制 `bf16` 以節省記憶體。由於 Mamba 模型沒有傳統 KV cache，但 SSM 隱藏狀態 (`h_prev`) 需以對應精度儲存。
- **狀態快取設計**：
  - 在生成過程中，每次 Decode 僅送入最後一個 token，同時傳入上一步的 `h_prev` (B, H, N, P) 與 `dt_cumsum`（用於 RoPE 相位）。Prefill 階段則不傳遞任何快取，平行計算所有 token 的隱藏狀態。

## 三、核心層的 MLX 復現（無 Triton 依賴）

### 3.1 自定義函數 (`ops.py`)

```python
import mlx.core as mx

def tanh_approx(x):
    return 2.0 * mx.sigmoid(2.0 * x) - 1.0

def scaled_tanh(x, scale=10.0):
    return tanh_approx(x * (1.0 / scale)) * scale

def silu(x):
    return x * mx.sigmoid(x)

def silu_gating(gate, feat):
    return silu(gate) * feat

def rope(x, angles):
    # x: (B, L, H, N, 2) 或類似
    sin, cos = mx.sin(angles), mx.cos(angles)
    # 應用標準旋轉位置編碼
    x1, x2 = x[..., 0], x[..., 1]
    return mx.stack([x1 * cos - x2 * sin, x2 * cos + x1 * sin], axis=-1)
```

### 3.2 TuckerMoE (`tucker_moe.py`)

原 Triton kernel 改為批次運算，並利用 MLX 的自動平行化：

- **前向**：
  1. 路由：`logits = router(x)`，`capped = scaled_tanh(logits, 10.0)`。
  2. 計算 temperature（由 `step` 決定 schedule，或由外部設定常數）。
  3. `router_probs = mx.softmax(capped / temp)`
  4. 選取 top-k 並計算正規化機率。
  5. `x_shared = mx.matmul(x, U_in)` → `RMSNorm`。
  6. 對於每個選中的專家 `e`：`G_e = mx.einsum("r, rst -> st", U_expert[e], core)`，然後 `out_e = mx.matmul(x_shared, G_e)`，加權總和。
  7. `out = mx.matmul(x_core, U_out) + bias`
- **損失**：負載平衡損失與 Z-loss 皆以 MLX 算子計算，無需自定義 backward。

### 3.3 Mamba3Block (`mamba_block.py`)

關鍵挑戰：平行掃描 (parallel scan) 在 MLX 中無內建 `associative_scan`。解決方案：**基於 chunk 內的密集轉移矩陣法**。

- **chunk_parallel_scan** 實作細節：
  - 輸入：`u_ssm` (B, L, H, N, P) 與 `dt_b` (B, L, H)，`A_b` (B, L, H)，`C_rotated` (B, L, H, N, R)。
  - 分割成 chunk：`u_c` (B, nc, chunk_size, H, N, P)，`la_c` = `dt_b * A_b` → (B, nc, chunk_size, H)。
  - **Chunk 內掃描**：對每個 chunk，建立 `Lc = chunk_size` 的下三角係數矩陣：
    - 計算 `alpha = mx.exp(la_c)` (B, nc, Lc, H)
    - 建立乘積矩陣 `M`：形狀 (B, nc, H, Lc, Lc)，其中 `M_{i,j} = prod_{k=j}^{i} alpha[:, k]`（當 j≤i，否則 0）。這可以透過 `mx.cumprod` 與視窗運算高效實現：
      ```python
      # 偽代碼
      alpha_log_cum = mx.cumsum(la_c, axis=2)  # (B, nc, Lc, H)
      # 擴展成差異矩陣
      log_M = alpha_log_cum[:, :, :, None] - alpha_log_cum[:, :, None, :]  # 利用廣播
      M = mx.exp(log_M) * mx.tri(Lc, Lc, k=0)  # 下三角 mask
      ```
    - 計算 `u_flat = u_c.reshape(B, nc, Lc, H*N*P)`，然後 `h_intra_flat = mx.matmul(M.reshape(B*nc*H, Lc, Lc), u_flat)`，再 reshape 回去。
    - 此方法在 `Lc=64` 時僅需少量記憶體，且能被 Metal 完全加速。
  - **跨 chunk 連接**：計算 `decay = mx.exp(mx.sum(la_c, axis=2))`，迭代計算 `h_prev`。
  - 輸出 `y` 與最終狀態 `h_prev`。

- **RoPE 應用**：計算 `angles = cumsum(dt_b * theta)`，然後對 B 與 C 使用 `rope`。
- **門控 SSM**：原版的 `lv, dv, av` 計算後，形成 `u_ssm` 輸入 scan。
- **輸出**：`y` 經過 `y_down_proj` 加上 skip connection 後，再進行閘控殘差。

### 3.4 TransformerBlock (`transformer_block.py`)

- Q/K/V 投影後，使用 `mx.fast.scaled_dot_product_attention` (支援 mask)。
- FFN 可選 MoE 或標準 SiLU 閘控。
- LayerScale 與殘差連接。

### 3.5 全模型 (`hybrid_model.py`)

- `TrueHybridMamba` 組合 Mamba3Block 與 TransformerBlock（比例 4:1）。
- `Mamba3LanguageModel` 包含 embedding、backbone、norm、lm_head。
- 支援 `use_activation_checkpoint` 以節省記憶體（MLX 中可透過 `mx.compile` 的 rematerialization 實現，但簡單作法可手動分段）。
- 權重載入時，注意 `lm_head.weight` 與 `embedding.weight` 共享（使用 `mx.array` 參考）。

## 四、Prefill / Decode 分離設計

生成迴圈必須區分兩個階段：

### 4.1 Prefill 階段

- **輸入**：完整 prompt token IDs。
- **模型呼叫**：`backbone(prompt_tokens)` 一次計算所有位置的隱藏狀態。
- **輸出**：最後一個位置對應的 logits，以及內部狀態（用於後續 decode）：
  - Mamba 狀態：最後一個 chunk 的 `h_prev`（B, H, N, P）及各頭的 `dt_cumsum`（用於 RoPE 相位）。
  - Attention 狀態：若未來使用 KV cache，此處會保存所有層的 K, V；但初期可省略，每次 decode 都重算 attention（因為 Mamba 層已捕獲長距，attention 層少，重算成本可接受）。
- **效能**：因序列長度一次性平行處理，需確保 MLX 充分平行化。對於極長 prompt，可啟用 chunk 分割以控制記憶體。

### 4.2 Decode 階段（自迴歸生成）

- **輸入**：僅上一步產生的單一 token ID。
- **模型呼叫**：`backbone(new_token, past_state=prefill_state)`，其中 `past_state` 包含：
  - Mamba 的 `h_prev` 與 `dt_cumsum`。
  - 所有層的隱藏狀態快取（選用）。
- **模型前向需修改**：每個 MambaBlock 接受可選的 `state` 參數，並在 forward 後返回更新後的 `state`。
  - Mamba SSM 掃描長度 `L=1` 時，遞迴公式化簡為 `h_new = exp(dt * A) * h_prev + u_ssm[0]`，無需呼叫 scan。此捷徑可大幅加速 decode。
  - 我們應在 decode 時直接使用公式計算，跳過 chunk_parallel_scan。
- **損失與路由**：decode 時仍需計算路由機率與對應專家輸出，並可選計算 Z-loss（若 training 則保留，推論可關閉或設為 0）。
- **logits 輸出**：僅取最後一個位置。

### 4.3 狀態管理與 KV cache

對於 Transformer 層，若希望加快 decode，可實作標準 KV cache。但考慮 MoE 注意力層數少，可先不實作，以簡化程式碼。但架構上要保留 `past_key_values` 槽位，以便未來擴充。

## 五、採樣策略完整實作 (`sampler.py`)

```python
import mlx.core as mx

def apply_repetition_penalty(logits, generated_ids, penalty, window):
    if penalty == 1.0 or len(generated_ids) == 0:
        return logits
    recent = generated_ids[-window:]
    # 找到重複 token 的位置
    unique_ids, counts = mx.unique(recent, return_counts=True)
    # 建立懲罰係數（對應出現次數）
    coeffs = mx.where(counts > 0, penalty, 1.0)
    # 廣播懲罰
    penalty_map = mx.zeros_like(logits)
    for i in range(len(unique_ids)):
        penalty_map = penalty_map.at[unique_ids[i]].set(coeffs[i])
    # 應用懲罰：除以係數（常見作法）或減去 (1-penalty)*logits
    # 這裡採用除以係數的方式
    return logits / mx.maximum(penalty_map, 1e-6)

def apply_frequency_presence_penalty(logits, generated_ids, pres_pen, freq_pen, window):
    if pres_pen == 0.0 and freq_pen == 0.0:
        return logits
    recent = generated_ids[-window:]
    unique_ids, counts = mx.unique(recent, return_counts=True)
    for i in range(len(unique_ids)):
        idx = unique_ids[i].item()
        count = counts[i].item()
        # OpenAI style: penalty = -pres_pen * (count > 0) - freq_pen * count
        logits = logits.at[idx].add(-pres_pen * (1 if count > 0 else 0) - freq_pen * count)
    return logits

def sample(logits, temperature, top_k, top_p, min_p, rng_key):
    logits = logits / temperature
    # Top-k
    if top_k > 0:
        topk_vals, topk_indices = mx.topk(logits, k=top_k)
        min_threshold = topk_vals[-1]
        logits = mx.where(logits < min_threshold, -float('inf'), logits)
    # Top-p (nucleus)
    if top_p < 1.0:
        sorted_logits = mx.sort(logits)[::-1]
        cumulative_probs = mx.cumsum(mx.softmax(sorted_logits), axis=-1)
        cutoff_idx = mx.argmax(cumulative_probs > top_p, axis=-1)
        cutoff_val = sorted_logits[cutoff_idx] if cutoff_idx < len(sorted_logits) else sorted_logits[-1]
        logits = mx.where(logits < cutoff_val, -float('inf'), logits)
    # Min-p
    if min_p > 0.0:
        probs = mx.softmax(logits)
        max_prob = mx.max(probs)
        min_threshold = max_prob * min_p
        logits = mx.where(probs < min_threshold, -float('inf'), logits)
    probs = mx.softmax(logits)
    token = mx.random.categorical(probs, key=rng_key)
    return token
```

**整合進 generate**：每步 decode 後，將 `logits` 依序經過 repetition penalty、presence/frequency penalty，再進入 `sample`。

## 六、投機解碼兼容性

### 6.1 架構設計

- 主模型 (`target_model`) 與草稿模型 (`draft_model`) 分開，草稿模型通常較小（例如精簡版 Mamba 或 Transformer）。
- 投機解碼流程：
  1. 使用 target model 的 prefill 計算 prompt logits，並抽樣得到第一個 token。
  2. 進入自迴歸 loop，每次迭代：
     - 用 target model decode 上一個 token，得到 `target_logits`。
     - 使用 draft model 自迴歸生成 K 個草稿 token（連同其機率分佈）。
     - 使用 target model 以並行方式（一次 prefill-like 計算）取得這 K 個位置的 logits。
     - 按順序比對 draft token 與 target 抽樣，進行 accept/reject。
     - 更新輸入序列，必要時重新計算 state（或利用快取）。
- 核心挑戰：target model 必須能對任意長度的序列（`[prefix, draft tokens]`）計算 logits。Mamba 支援此種並行計算，只需修改 forward 以接受從某狀態起始的 prefix。

### 6.2 實作細節

- 因為 MLX 沒有 `past_key_values`，每次驗證時可從最近的快取狀態繼續，避免重複計算整個歷史。
- 草稿模型可為輕量 Transformer (如 2 層、d_model=256) 或用 n-gram 模型（需額外實作）。
- 驗證函數：`speculative_verify(target_model, draft_model, state, token_sequence, K)` 返回 accepted tokens 與更新後的 state。

## 七、編譯與效能優化

### 7.1 `mx.compile` 的使用

- **推薦參數 `--full-decode-compile`**：將 decode 步驟的整個函數以 `mx.compile` 包裹，觸發 MLX 的 JIT 編譯，生成 Metal 圖，減少 dispatch overhead。
- 範例：
  ```python
  @mx.compile
  def decode_step(model, x, state, step):
      # 處理 single token 的 forward
      logits, new_state = model(x, past_state=state, step=step)
      return logits, new_state
  ```
- 注意：編譯需要固定輸入形狀，因此 token ID 張量形狀在 decode 時固定為 (1, 1)，即 batch=1, seq_len=1。

### 7.2 Prefill 的平行化

- Prefill 長度可變，可能需要 dynamic shape，`mx.compile` 對動態形狀支援有限，故 prefill 可保持 eager 模式或使用 `mx.compile` 搭配 `mx.Shape` 註記。

### 7.3 記憶體管理

- 採用 `mx.bfloat16` 可將權重記憶體減半。使用 `--kv-dtype auto` 時，KV 相關張量也將使用 bf16。
- 對於 Mamba 的狀態張量，維持與計算一致的精度（如 bf16），避免轉換開銷。

## 九、驗證與測試計畫

1. **單元測試**：針對 `TuckerMoE`、`chunk_parallel_scan`、`sampler` 等模組，使用固定輸入與 PyTorch 輸出比對。
2. **狀態傳遞正確性**：比較同一個 prompt，使用 prefill-only 一次性計算與逐步 decode 取得的 logits 序列是否一致（給定相同的隨機種子）。
3. **端到端生成**：在小型模型（如 d_model=128，層數=2）上，確保 MLX 與 PyTorch 版本 greedy 輸出完全匹配。
4. **投機解碼驗證**：確保啟用 speculative 後，產生的文字與普通解碼相同（當 accept 全拒絕時等價，且所有 accept 時應加速）。
5. **效能測試**：量測各種參數下的 tokens/sec，並與無編譯版本對比。

## 十、潛在挑戰與應對

- **MLX 缺乏 `mx.scan`**：已透過密集矩陣法解決 chunk 內掃描。未來可嘗試貢獻 Metal 核來加速長 chunk。
- **動態 shape 編譯**：若 prefill 長度變化大，可固定幾個常用長度並產生不同的編譯版本。
- **記憶體峰值**：Transformer 注意力在長 prompt 可能暴增，但 Mamba 層佔主體，應可控；亦可實作 Flash Attention（MLX 內建 `sdpa` 已是高效實作）。
- **路由損失在推論時計算**：應在推論時關閉或設為 0，以免額外運算。
