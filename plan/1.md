### 一、N-gram 初始化：提升 Jacobi 初始猜测质量

**原理**：Jacobi 解码的收敛速度高度依赖初始猜测。用简单的“复制最后一个 token”初始化，信息量极低。N-gram 缓存可基于历史生成上下文提供更合理的初始序列，减少所需修正轮数。

**实现步骤**：

1. **构建动态 N-gram 缓存**
   - 在生成过程中，维护一个字典 `ngram_cache`（最大容量 10000 条）。
   - 每次生成一个 token 后，将最后 `n` 个 token 的上下文作为键，下一个 token 作为值存入。
   - 键格式：`tuple(context_tokens)`，值：`[token_id]`（可扩展为出现次数列表，支持概率选择）。

2. **生成初始猜测**
   - 给定当前前缀 `prefix`，取最后 `n` 个 token 作为查询键。
   - 在缓存中查询匹配的后续 token 列表。如果命中，按出现频率采样一个 token 作为第一个猜测，然后以该 token 更新上下文，继续查询后续 token，直至得到 `N` 个猜测或缓存未命中。
   - 未命中部分用 `prefix[-1]` 填充。

3. **集成到 Jacobi 循环**
   - 在 `jacobi_generate` 函数的“初始猜测”步骤，调用 `ngram_initialize(prefix, N)` 代替原来的 `[prefix[-1]] * N`。
   - 每次 Jacobi 收敛确认 token 后，立即用这些 token 更新 n-gram 缓存。

**伪代码示例**：

```python
class NGramCache:
    def __init__(self, n=3, max_size=10000):
        self.n = n
        self.cache = {}  # key: tuple(int), value: list(int)
        self.max_size = max_size

    def update(self, tokens):
        for i in range(len(tokens) - self.n):
            key = tuple(tokens[i:i+self.n])
            next_tok = tokens[i+self.n]
            if key not in self.cache:
                self.cache[key] = []
            self.cache[key].append(next_tok)
            if len(self.cache) > self.max_size:
                # 简易淘汰：随机删除一个键
                del self.cache[random.choice(list(self.cache.keys()))]

    def query(self, context):
        key = tuple(context[-self.n:])
        if key in self.cache and self.cache[key]:
            return random.choice(self.cache[key])
        return None

def ngram_initialize(prefix, N, cache):
    guesses = []
    context = prefix[:]
    for _ in range(N):
        next_tok = cache.query(context)
        if next_tok is None:
            next_tok = context[-1]  # 回退为复制
        guesses.append(next_tok)
        context.append(next_tok)
    return guesses
```

**验证方法**：

- 选取 50 条 CoT 样本，记录使用随机复制初始化与 N-gram 初始化时的平均收敛轮数。
- 比较整体生成延迟（tok/s），预期 N-gram 初始化可减少 0.5-1 轮迭代。

### 二、Rejection Recycling：复用投机修正中部分正确的 token

**原理**：在并行修正时，如果 `guesses` 和 `new_guesses` 在某位置不匹配，但该位置之前的连续匹配段已经确定正确，这部分 token 可以直接接受，而不必重新生成。这相当于在 Jacobi 内部嵌入了投机解码的“部分接受”机制，可提高单次迭代的平均产出。

**实现方式**：

- 在 Jacobi 修正循环中，找到第一个不匹配位置 `j` 后，**直接将 `guesses[0:j]` 作为正式输出 token 加入生成结果**，然后将 `j` 之后的未收敛部分继续迭代。
- 注意：为保持正确性，应确保前缀部分包含这些已接受的 token，以便下一次前向拥有完整上下文。

**对 Jacobi 循环的修改**：

1. 添加一个 `output_tokens` 列表存放已接受的 token。
2. 每轮迭代修正后，若 `mismatch > 0`，则将 `guesses[:mismatch]` 追加到 `output_tokens`，同时更新 `prefix += guesses[:mismatch]`，然后将猜测序列截断为 `guesses[mismatch:]`，长度可能不足 N，用新随机 token 补齐，继续迭代。
3. 若全部匹配（`mismatch == N`），则接受全部 N 个 token，本轮结束。
4. 如果达到最大迭代次数仍未全部收敛，则用主模型的 logits 强制生成一个 token（类似自回归），并将该 token 加入输出。

**伪代码片段**（集成到 Jacobi 循环中）：

```python
accepted_tokens = []
while len(accepted_tokens) < max_new:
    guesses = ngram_initialize(prefix, N, cache)
    for it in range(max_iters):
        full_seq = mx.array(prefix + guesses)
        logits = model(full_seq)
        new_guesses = [sample(logits[i], T) for i in range(-N, 0)]

        # 找第一个不匹配位置
        j = 0
        while j < len(guesses) and guesses[j] == new_guesses[j]:
            j += 1

        if j > 0:
            # 接受前 j 个 token
            accepted_tokens.extend(guesses[:j])
            prefix.extend(guesses[:j])
            guesses = guesses[j:] + [prefix[-1]] * j  # 补齐长度
            if len(guesses) < N:
                guesses += [prefix[-1]] * (N - len(guesses))

        if j == N:  # 全部收敛
            accepted_tokens.extend(guesses)
            prefix.extend(guesses)
            break

        # 未全部匹配，用新猜测替换未匹配部分
        guesses = new_guesses[j:] + guesses[j:]  # 或简单 new_guesses 替换，注意调整长度
        # 确保长度为 N
        guesses = (guesses + [prefix[-1]] * N)[:N]
    else:  # 迭代结束仍未全部收敛，单步生成一个 token
        single_logit = model(mx.array(prefix))[-1]
        next_tok = sample(single_logit, T) if T > 0 else argmax(single_logit)
        accepted_tokens.append(next_tok)
        prefix.append(next_tok)
    # 更新缓存
    cache.update(prefix)
```

**验证方法**：

- 记录 Jacobi 每轮迭代平均接受的 token 数量（ARL，Accepted Tokens per Round）。
- 对比开启/关闭 Rejection Recycling 时的 ARL 和整体 tok/s。预期 ARL 提升 0.5-1.5 个 token。

### 三、Lookahead Decoding：并行猜测 n-gram 并进行批量验证

**原理**：Lookahead Decoding 将 Jacobi 迭代中产生的高置信度 n-gram 片段缓存起来，然后直接将这些片段作为“草稿”进行投机解码式的并行验证。它巧妙结合了 Jacobi 的并行猜测和投机解码的一次性验证，进一步降低平均生成延迟。

**核心流程**：

1. **生成池**：维护一个临时的 n-gram 缓存（Lookahead Cache），记录 Jacobi 迭代过程中匹配的连续 token 序列。
2. **草稿构建**：从当前前缀出发，在缓存中查找最长的匹配 n-gram（例如连续 3-6 个 token），将该 n-gram 作为草稿 token。
3. **并行验证**：将草稿 token 直接追加到前缀，送入主模型做一次前向验证（类似投机解码的验证步骤）。如果全部匹配，则接受整个草稿；否则，从第一个不匹配处截断，并将新 token 作为修正结果。
4. **缓存更新**：将被接受的 token 序列加入缓存，持续积累。

**集成方式**：

- 在你的 Jacobi 解码主循环中，**将 Lookahead 作为第一优先级**：每次生成开始时，先尝试用 Lookahead Cache 构建草稿并验证。如果草稿被接受，则跳过 Jacobi 迭代；否则回退到 Jacobi 流程。
- Lookahead Cache 与 N-gram Cache 可以合并或独立：Lookahead 缓存要求键值对为连续 token 序列（value 为后续 token 序列），且验证时使用贪婪匹配，不接受采样。

**伪代码**：

```python
class LookaheadCache:
    def __init__(self, max_len=6, max_size=5000):
        self.max_len = max_len
        self.cache = {}  # key: tuple, value: list of tokens
        self.max_size = max_size

    def update(self, tokens):
        for i in range(1, self.max_len+1):
            if len(tokens) >= i+1:
                key = tuple(tokens[-i-1:-1])
                if key not in self.cache:
                    self.cache[key] = []
                # 存储连续后续
                self.cache[key].append(tokens[-1])

    def query_longest(self, context):
        # 从最长可能匹配开始找
        for l in range(min(len(context), self.max_len), 0, -1):
            key = tuple(context[-l:])
            if key in self.cache and self.cache[key]:
                # 简单返回最常见的下一个 token，并尝试扩展成多 token
                next_tok = max(set(self.cache[key]), key=self.cache[key].count)
                draft = [next_tok]
                # 尝试继续扩展
                ext_context = context + draft
                for _ in range(l):  # 最多再扩展 l 个
                    ext_key = tuple(ext_context[-l:])
                    if ext_key in self.cache and self.cache[ext_key]:
                        next_tok = max(set(self.cache[ext_key]), key=self.cache[ext_key].count)
                        draft.append(next_tok)
                        ext_context.append(next_tok)
                    else:
                        break
                return draft
        return None

def speculative_verify(model, prefix, draft_tokens):
    # 复用你已有的并行验证逻辑（如 generate_spec_token_stream 里的 verify 部分）
    full = mx.array(prefix + draft_tokens)
    logits = model(full)
    accepted = []
    for i, draft_tok in enumerate(draft_tokens):
        model_tok = argmax(logits[len(prefix)+i])
        if draft_tok == model_tok:
            accepted.append(draft_tok)
        else:
            accepted.append(model_tok)
            break
    return accepted  # 返回接受的 token 列表（包括可能的修正）

# 主循环融合
while len(output) < max_new:
    # 1. 尝试 Lookahead
    draft = lookahead_cache.query_longest(prefix)
    if draft:
        accepted = speculative_verify(model, prefix, draft)
        if accepted:
            output.extend(accepted)
            prefix.extend(accepted)
            lookahead_cache.update(prefix)
            ngram_cache.update(prefix)
            continue  # 本轮结束，跳回
    # 2. 回退到 Jacobi + N-gram + Recycling
    ... (前面实现的 Jacobi 增强循环)
```

**验证方法**：

- 分别测量 Lookahead 命中率（草稿被调用的比例）和接受率。
- 整体对比开启 Lookahead 后的 tok/s 提升，预期在重复性高的 CoT 文本上可获得 1.5x-2.3x 加速。
