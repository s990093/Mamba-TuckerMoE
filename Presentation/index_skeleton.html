O(N) KV
KV Cache Growth
Pure transformer KV cache grows linearly. At 32K context → OOM on M2 Pro. Mamba SSM state = 14.1 MiB constant.
BW-Bound
Standard MoE
Loading K=2 dense expert matrices per token = 8 GB/token BW. Unified memory bottleneck.

Can we build a 2.4B dense-equivalent model that fits on a 16 GB device, supports 32K context, and runs at practical speed using Tucker-decomposed MoE?

Mamba-3 State Space Model5 / 12
Core SSM Equations — Trapezoidal Discretization
$\bar{A}_t = \exp(\Delta_t A)$   $\bar{B}_t = \tfrac{\Delta_t}{2}(\bar{A}_t + I)B_t$
$h_t = \bar{A}_t\,h_{t-1} + \bar{B}_t\,x_t$   $y_t = C_t\,h_t + D\,x_t$
Trapezoidal midpoint (vs Euler) · reduces discretization error · enables longer effective receptive field
🧠
O(1) State Memory
SSM hidden state is fixed-size regardless of sequence length. 14.1 MiB at 32K context vs KV cache O(N).
📏
32K Context Window
Mamba-3 trapezoidal discretization enables long sequences without quadratic cost. Dense FFN OOM >16 GB.
🔄
RoPE on B, C Matrices
Rotary positional embeddings applied to input/output projection matrices. Injects relative position without recurrence modification.
⚡
Chunk-Wise Parallel Scan
Training via chunk parallelism. Inference via sequential O(1) recurrence. MLX bf16 compile: 47→70 tok/s baseline.

Tucker Decomposition Principle6 / 12
Core Decomposition Formula
$W_e \approx U_{in} \cdot Core_e \cdot U_{out}$
Uin: 1536×256 · shared across all experts
Coree: 32×512×256 · unique per expert (built from 32 shared slices)
Uout: 512×6144 · shared across all experts
How Coree is built — per-expert weighted sum:
$Core_e = \sum_{r=1}^{32} u_r^{(e)} \cdot Core[r,:,:]$
32 shared slices × per-expert weight vector → unique Coree
