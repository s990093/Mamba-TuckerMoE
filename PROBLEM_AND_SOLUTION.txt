📌 THE PROBLEM
────────────────────────────────────────────────────────────────────────────────
CoT 推理品質下降是由於 cot_format_fsm.py 中的 token ID 識別失敗。

ROOT CAUSE（根本原因）
─────────────────────
分詞器報告 vocab_size = 32000，但實際後端詞彙表有 32007 個 token。
CoT 特殊 token（32002-32005）超出了邊界檢查，被拒絕。

代碼退回到使用 '</' (ID 829) 作為關閉目標，而不是正確的：
  - </think>  (32003)
  - </final>  (32005)

這導致：
  1. Close bias 應用於錯誤的 token
  2. FSM 永遠看不到正確的關閉標籤
  3. 推理模式轉換失敗
  4. 生成品質下降


🔧 THE SOLUTION
────────────────────────────────────────────────────────────────────────────────
修改 build_format_guard() 使用實際的後端詞彙大小：

BEFORE:
  if tid is not None and 0 <= tid < vocab_size:  # 32000
      close_map[mode] = tid

AFTER:
  # 獲取實際詞彙大小
  actual_vocab_size = vocab_size
  if hasattr(tokenizer, "backend_tokenizer"):
      backend_vocab = tokenizer.backend_tokenizer.get_vocab()
      if backend_vocab:
          actual_vocab_size = max(actual_vocab_size,
                                 max(backend_vocab.values()) + 1)

  if tid is not None and 0 <= tid < actual_vocab_size:  # 32007
      close_map[mode] = tid

AFTER FIX:

    between→32004 `<final>`,
    final→32005 `</final>`
  ]
