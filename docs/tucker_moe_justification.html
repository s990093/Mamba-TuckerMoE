Tucker-MoE 有效性論證 數學版

從 dense MoE 出發，先確立 Tucker 是「真的能壓縮、有精確性保證」的分解；
再正面回答核心困惑：SVD / Tucker 古典上都是「先訓 dense 再壓縮」，反過來從零直接訓因子，憑什麼可以？

對應程式碼：model.py（TritonTuckerMoE，含反向傳播）、 tucker_moe.py（MLX 推論版）。維度取自 Mamba3Config： \(E=8,\ \text{top-}k=2,\ r_1=4,\ r_2=1024,\ r_3=256\)。

1. 從 Dense MoE 出發

標準（dense）MoE 對輸入 \(x\in\mathbb{R}^{d_{\text{in}}}\)：

\[ \begin{aligned} \text{router:}\quad & p = \operatorname{softmax}\!\big(W_r^\top x\big), && W_r\in\mathbb{R}^{d_{\text{in}}\times E}\\[2pt] \text{expert } e:\quad & y_e = W_e^\top x, && W_e\in\mathbb{R}^{d_{\text{in}}\times d_{\text{out}}}\\[2pt] \text{output:}\quad & \mathrm{out} = \sum_{k=1}^{K} p_{e_k}\, y_{e_k}, && K=\text{top-}k \end{aligned} \]

把所有專家權重堆成三維張量

\[ \mathcal{W}\in\mathbb{R}^{E\times d_{\text{in}}\times d_{\text{out}}},\qquad \mathcal{W}_{e,:,:}=W_e . \]

參數量隨專家數線性爆炸（以 gate_proj，\(d_{\text{in}}=768,\ d_{\text{out}}=4608\) 為例）：

\[ P_{\text{dense}} = E\,d_{\text{in}}\,d_{\text{out}} + d_{\text{in}}E \;=\; 8\cdot768\cdot4608 = 28{,}311{,}552 . \]
關鍵觀察。 各專家處理同一語意空間，方向高度重疊，故 \(\mathcal{W}\) 各 mode 的展開 \(\mathcal{W}_{(n)}\) 秩遠低於維度： \(\operatorname{rank}\mathcal{W}_{(1)}\ll E,\ \operatorname{rank}\mathcal{W}_{(2)}\ll d_{\text{in}},\ \operatorname{rank}\mathcal{W}_{(3)}\ll d_{\text{out}}\)。這是低秩（Tucker）分解的切入點。

2. 三步低秩約束 = Tucker 分解

  1. 輸入 mode（共享 \(U_{\text{in}}\)）： \(\ x_{\text{shared}} = \operatorname{RMSNorm}\!\big(U_{\text{in}}^\top x\big)\in\mathbb{R}^{r_3},\quad U_{\text{in}}\in\mathbb{R}^{d_{\text{in}}\times r_3}.\)
  2. 專家 mode（core 共享，專家僅以 \(r_1\) 維係數區分）： \[ G^{(e)} = \sum_{a=1}^{r_1}(U_{\text{expert}})_{e,a}\,\mathcal{G}_{a,:,:}\in\mathbb{R}^{r_3\times r_2}, \qquad x_{\text{core}} = \sum_{k=1}^{K} p_{e_k}\big(G^{(e_k)}\big)^\top x_{\text{shared}} . \]
  3. 輸出 mode（共享 \(U_{\text{out}}\)）： \(\ \mathrm{out} = U_{\text{out}}^\top x_{\text{core}} + \beta,\quad U_{\text{out}}\in\mathbb{R}^{r_2\times d_{\text{out}}}.\)

每個專家的等效權重 \(W_e = U_{\text{in}}\,G^{(e)}\,U_{\text{out}}\)，整個張量寫成標準 Tucker：

\[ \boxed{\;\mathcal{W} = \mathcal{G}\times_1 U_{\text{expert}}\times_2 U_{\text{in}}\times_3 U_{\text{out}}^\top\;} \qquad \mathcal{W}_{e,i,j}=\sum_{a,b,c}\mathcal{G}_{a,b,c}\,(U_{\text{expert}})_{e,a}(U_{\text{in}})_{i,b}(U_{\text{out}})_{c,j}. \]

multilinear rank \(=(r_1,r_3,r_2)=(4,256,1024)\)。唯一偏離純線性 Tucker 之處：步驟 1 的 \(\operatorname{RMSNorm}\)（見 §5.3、§4.5）。

3. Tucker 壓縮的有效性與精確性保證

先把「Tucker 到底是不是一個正當的壓縮、誤差能不能控制」講死。這一節完全站在古典逼近論立場（給定 \(\mathcal{W}\)），下一節才處理「反過來」。

3.1 完備性：full rank 時無損 —— 它是「精確的基底重寫」，不是近似

當 \((r_1,r_3,r_2)=(E,d_{\text{in}},d_{\text{out}})\) 時，Tucker 分解恆等成立（任何張量都有 HOSVD）：

\[ \mathcal{W} = \mathcal{G}\times_1 U^{(1)}\times_2 U^{(2)}\times_3 U^{(3)},\qquad U^{(n)}\ \text{正交},\quad \|\mathcal{W}-\hat{\mathcal{W}}\|=0 . \]

也就是說 Tucker 本身不丟資訊——它只是把張量換到「各 mode 的奇異向量基底」下表示，core \(\mathcal{G}\) 是 \(\mathcal{W}\) 在該基底的座標。壓縮只發生在「截斷」那一步，而截斷的誤差是可量化的（§3.2）。這保證了：我們做的不是某種啟發式塌縮，而是有完備理論的基底分解。

3.2 截斷的精確性保證：HOSVD 誤差界

令 \(\sigma^{(n)}_i\) 為 mode-\(n\) 展開 \(\mathcal{W}_{(n)}\) 的第 \(i\) 個奇異值。把各 mode 截到秩 \(r_n\)，HOSVD 給出可計算的誤差上界：

\[ \big\|\mathcal{W}-\hat{\mathcal{W}}_{\text{HOSVD}}\big\|_F^{2}\;\le\;\sum_{n=1}^{3}\ \sum_{i> r_n}\big(\sigma^{(n)}_i\big)^2 , \]

且 HOSVD 與「最佳 Tucker 近似」只差一個 \(\sqrt{N}\) 常數（\(N=3\) 個 mode）：

\[ \big\|\mathcal{W}-\hat{\mathcal{W}}_{\text{HOSVD}}\big\|_F\;\le\;\sqrt{3}\,\big\|\mathcal{W}-\hat{\mathcal{W}}_{\text{opt}}\big\|_F . \]
這就是「保證精確性」的精確意義：丟掉的誤差 = 被截掉的奇異值平方和。它是矩陣 Eckart–Young 定理（\(\|W-W_r\|_F^2=\sum_{i>r}\sigma_i^2\)）的高階張量版。要更準可用 HOOI/ALS 迭代逼近 \(\hat{\mathcal{W}}_{\text{opt}}\)。

3.3 壓縮 ↔ 精度：選 rank 就是選誤差上界

於是「壓縮」是一條有刻度的 trade-off：rank 越低，參數越少，§3.2 的尾巴越肥（誤差越大）。本專案選 \((4,256,1024)\) 等於宣稱「\(\mathcal{W}\) 的奇異值在這些 rank 之後衰減夠快，尾巴可忽略」——這是一個可被 §8 ablation 檢驗的經驗假設，而非信仰。

4. 為何「反過來」從零訓練因子可以（核心）

你的困惑（完全合理）。 §3 的所有保證都建立在「已經有一個 \(\mathcal{W}\)」之上——SVD/Tucker 是逼近論，需要一個被逼近的對象。 但我們從零隨機初始化、直接訓練因子，從不存在 dense \(\mathcal{W}\)。沒有對象可逼近，「壓縮」「精度保證」還剩什麼意義？

4.1 釐清：你把「兩個不同的問題」混成一個了

① 壓縮（approximation）② 低秩參數化（hypothesis class）
問題給定 \(\mathcal{W}^\star\)，求最近的低秩 \(\hat{\mathcal{W}}\)在所有低秩張量中，求任務損失最小者
需要 target？需要 \(\mathcal{W}^\star\)不需要，只需任務損失 \(\mathcal{L}\)
目標\(\min\|\mathcal{W}^\star-\hat{\mathcal{W}}\|\)\(\min_{\mathcal{W}\in\mathcal{M}_r}\mathcal{L}(\mathcal{W})\)
本專案—（不做）← 我們做的是這個

古典 SVD/Tucker 是 ①。我們做的是 ②：把模型權重參數化成低秩，然後做標準的經驗風險最小化（ERM）。② 根本不是逼近，沒有 target，所以「沒有 \(\mathcal{W}^\star\) 可逼近」不是缺陷——它本來就不需要。

這跟「CNN 把全連接限制成卷積」「用 MLP 而非查表」是同一回事：我們限制假設空間當作歸納偏置，從不問「那你在逼近哪個全連接層？」——沒有那個層，我們直接在受限空間裡訓練。把低秩當成「壓縮一個既有 dense」只是歷史路徑，不是邏輯必需。

4.2 「反過來」= 在低秩流形 \(\mathcal{M}_r\) 上做 ERM

\[ \mathcal{M}_r=\big\{\mathcal{W}:\operatorname{rank}\mathcal{W}_{(1)}\le r_1,\ \operatorname{rank}\mathcal{W}_{(2)}\le r_3,\ \operatorname{rank}\mathcal{W}_{(3)}\le r_2\big\}. \]

因子 \((\mathcal{G},U^{(1)},U^{(2)},U^{(3)})\) 是 \(\mathcal{M}_r\) 的一個滿覆蓋參數化：任何 \(\mathcal{W}\in\mathcal{M}_r\) 都能被某組因子表示（§3.1 完備性的直接推論）。所以對因子做梯度下降，等價於在 \(\mathcal{M}_r\) 上直接搜尋任務最優解。可達集合與「post-hoc 截斷」完全相同，表達力不打折。

4.3 橋接：§3 的古典誤差界，其實正是 from-scratch 的精度保證

這是回答你「憑什麼保證精度」的關鍵。設任務損失 \(\mathcal{L}\) 對權重張量在工作區域 \(L\)-Lipschitz（輸入有界時成立）。令 \(\mathcal{W}^\star_{\text{dense}}\) 為假想的 dense 最優解，\(\Pi_r\) 為其 HOSVD 投影到 \(\mathcal{M}_r\)。則 \(\Pi_r\mathcal{W}^\star_{\text{dense}}\in\mathcal{M}_r\) 是一個可行點，因此

\[ \min_{\mathcal{W}\in\mathcal{M}_r}\mathcal{L}(\mathcal{W}) \;\le\; \mathcal{L}\big(\Pi_r\mathcal{W}^\star_{\text{dense}}\big) \;\le\; \mathcal{L}\big(\mathcal{W}^\star_{\text{dense}}\big) + L\underbrace{\sqrt{\textstyle\sum_{n}\sum_{i> r_n}(\sigma^{(n)}_i)^2}}_{\text{§3.2 的 HOSVD 尾巴}} . \]
解讀。 最好的低秩模型，其任務損失與「dense 最優」的差距，被 §3.2 那條 Eckart–Young/HOSVD 尾巴 \(\times\,L\) 界住。 古典壓縮的誤差界沒有消失，而是「轉移」成了 from-scratch 模型的精度上界。 而 from-scratch 訓練直接最小化左式 \(\min_{\mathcal{M}_r}\mathcal{L}\)，所以它達到的損失 \(\le\) 這個上界。 注意：\(\mathcal{W}^\star_{\text{dense}}\) 只出現在證明裡，演算法從不計算它——這就是為什麼不需要真的先訓 dense。

4.4 主導性：post-hoc 的輸出只是 from-scratch 的一個可行點

把 §4.3 的不等式再讀一次：post-hoc 給的 \(\Pi_r\mathcal{W}^\star_{\text{dense}}\) 只是 \(\mathcal{M}_r\) 裡一個特定點；from-scratch 在整個 \(\mathcal{M}_r\) 上找最小。故（在最佳化成功的前提下）

\[ \mathcal{L}\big(\text{from-scratch}\big)\;\le\;\mathcal{L}\big(\text{post-hoc}\big). \]

換句話說，post-hoc 唯一多給你的東西是一個好的起點（warm start）；它並沒有給你 from-scratch 達不到的解。我們用「好初始化 + 正規化 + 輔助損失」替代那個起點即可。

4.6 那什麼時候才該用 post-hoc？

當你已擁有訓練好的強 dense 模型、只為部署壓縮（warm-start 有現成價值），post-hoc 較省事。 但本專案是「在 16GB 預算下從零訓練自己的模型」——根本不該、也付不起先訓一個 2.4B dense 再壓。 此時 §4.1 的觀念轉換（壓縮≠逼近）+ §4.3 的精度橋接，說明 from-scratch 既合法、又免去最貴的步驟，且 §4.4 顯示它不會比 post-hoc 差。

5. 為何不塌縮成單一矩陣？SVD 壓縮效果如何維持

常見疑慮。 \(W_e = U_{\text{in}}\,G^{(e)}\,U_{\text{out}}\) 代數上等於某個單一矩陣 \(M_e\)，那不就「只是換個方式存一個矩陣」？壓縮在哪？

5.1 「塌縮成一個矩陣」正是低秩壓縮的定義，不是缺陷

固定專家 \(e\) 時三連乘確實塌縮成 \(M_e := U_{\text{in}}G^{(e)}U_{\text{out}}\in\mathbb{R}^{d_{\text{in}}\times d_{\text{out}}}\)。但 \(M_e\) 不是任意矩陣，其秩被瓶頸卡住：

\[ \operatorname{rank}(M_e)\le\min(r_3,r_2)=256<\min(d_{\text{in}},d_{\text{out}})=768 . \]

秩-\(r\) 的 \(m\times n\) 矩陣存因子只需 \(r(m+n)\) 個數而非 \(mn\)：滿秩 \(M_e=3{,}538{,}944\) 個自由度，秩-256 只 \(r(d_{\text{in}}+d_{\text{out}})=1{,}376{,}256\)。

「塌縮」與「壓縮」是同一件事： skinny 矩陣連乘 = 低秩矩陣。壓縮沒因塌縮消失；壓縮就是「塌縮後被約束在低秩」。前提是 rank 別開太大（\(r_3,r_2<\min(d_{\text{in}},d_{\text{out}})\)），否則 \(M_e\) 可滿秩，存因子反而更貴。

5.2 Tucker 就是高階 SVD（HOSVD）—— SVD 壓縮不但保留，還更強

矩陣 SVD 本身是 2-mode Tucker：\(W=U\Sigma V^\top=\Sigma\times_1 U\times_2 V\)。本專案是 3-mode，沿 expert/input/output 三軸同時低秩。且比「每專家各做一次秩-\(r\) SVD」更省，因為共同子空間被抽出共享：

\[ \text{獨立 SVD：}\;E\cdot r(d_{\text{in}}+d_{\text{out}}) \quad\text{vs}\quad \text{Tucker：}\;d_{\text{in}}r_3 + r_2 d_{\text{out}} + r_1 r_3 r_2 + \underbrace{E r_1}_{E\,\text{只乘}\,r_1}. \]

專家越多差距越大（§6.2）。

5.3 整層為何不塌縮成單一線性映射？（MoE 的真正答案）

§5.1 講「單一固定專家」。但整層輸出是輸入條件式的，不是任何固定矩陣的線性映射：

\[ f(x)=U_{\text{out}}^\top\Big[\sum_{k=1}^{K}\underbrace{p_{e_k}(x)}_{\text{非線性 gate}}\big(G^{(e_k(x))}\big)^\top\underbrace{\operatorname{RMSNorm}(U_{\text{in}}^\top x)}_{\text{非線性}}\Big]+\beta . \]

三處破壞全域線性：\(\operatorname{RMSNorm}\)（輸入相依縮放）、\(\operatorname{softmax}\)（非線性 gating）、\(\operatorname{topk}\)（離散、把輸入空間切成 \(\binom{E}{k}\) 個區域）。故 \(f\) 是分段、由 \(E\) 個低秩映射加權混成的非線性函數——容量來自 gated 組合數，遠超單一線性映射。

6.3 直擊 decode 瓶頸：記憶體頻寬而非 FLOP

top-\(k\) 固定時 FLOP 與 dense 同數量級 \(\big(d_{\text{in}}r_3+K r_3 r_2+r_2 d_{\text{out}}\sim\mathcal{O}(\text{FLOP}_{\text{dense}})\big)\)， 但權重足跡縮小 \(4.7\!-\!37.6\times\)、共享 \(\mathcal{G},U_{\text{out}}\) 常駐——省的是記憶體與每 token 串流的權重量，剛好打在單流 decode 的頻寬瓶頸上。

7. 反向傳播的數學

令上游梯度 \(\delta=\partial\mathcal{L}/\partial x_{\text{core}}\in\mathbb{R}^{r_2}\)。核心 FusedLatentMoE 手寫三個梯度：

\[ \frac{\partial\mathcal{L}}{\partial x_{\text{shared}}}=\sum_{k}p_{e_k}G^{(e_k)}\delta,\qquad \frac{\partial\mathcal{L}}{\partial p_{e_k}}=\big\langle\delta,(G^{(e_k)})^\top x_{\text{shared}}\big\rangle, \] \[ \frac{\partial\mathcal{L}}{\partial G^{(e)}}=\sum_{b}\sum_{k:\,e_k^{(b)}=e}p^{(b)}_{e_k}\,x^{(b)}_{\text{shared}}\big(\delta^{(b)}\big)^\top\quad(\text{外積累加}). \]

其餘沿 Tucker 鏈由 autograd 處理：

\[ \frac{\partial\mathcal{L}}{\partial\mathcal{G}_{a}}=\sum_e (U_{\text{expert}})_{e,a}\frac{\partial\mathcal{L}}{\partial G^{(e)}},\quad \frac{\partial\mathcal{L}}{\partial(U_{\text{expert}})_{e,a}}=\big\langle\mathcal{G}_a,\tfrac{\partial\mathcal{L}}{\partial G^{(e)}}\big\rangle,\quad \frac{\partial\mathcal{L}}{\partial U_{\text{out}}}=x_{\text{core}}\delta^\top . \]
topk 不可微： \(\partial e_k/\partial(\cdot)=0\)，選擇集合無梯度。故 router 訓練需靠 \(\mathcal{L}_{\text{lb}}\)（load-balance）與 \(\mathcal{L}_z\)（z-loss）供給訊號，否則退化為單專家。

8. 如何「證明」它真的有效（ablation 計畫）

  1. Rank–容量 Pareto： 掃 \(r_1\in\{2,4,8\},\ r_2\in\{512,1024,2048\},\ r_3\in\{128,256,512\}\)，畫 \(\mathcal{L}_{\text{val}}\) vs \(P_{\text{tucker}}\)，證明 §3.3 / §4.5 的「尾巴可忽略」假設成立、\((4,256,1024)\) 非欠擬合。
  2. From-scratch vs Post-hoc： 對照 (a) 同預算 dense MoE、(b) 訓練 (a) 後 Tucker 截斷+微調、(c) 本專案。預期 \(\mathcal{L}^{(c)}\le\mathcal{L}^{(b)}\)（§4.4），且 (c) 無需訓練 (a)。
  3. 有效秩檢查： 對 \(G^{(e)}\) 做 SVD，看奇異值譜 \(\sigma_i(G^{(e)})\) 是否用滿 \(r_2\)（驗證 §3.1–3.2 的截斷假設）。
  4. 專家分化： 統計 router 對各 category 的負載，確認 \(\mathcal{L}_{\text{lb}}\) 使分工成立。
  5. 端到端： 壓縮率 + perplexity + CoT 正確率，對齊 417M / 2.4B / 82.87%。

9. 下一步與研究方向（應用場景）

9.1 下一步：把 §8 跑成可發表的完整性

近期、收斂導向的工作，目標是讓每條 claim（C1–C5）各自被證偽過：

  1. 小規模 dense head-to-head： 在能同時訓 dense 與 Tucker 的尺度做受控對照，證明「等品質下參數少 \(N\times\)」的趨勢，避開「2.4B dense 訓不動」的陷阱，再外推到大模型。
  2. from-scratch vs post-hoc： 對照「訓 dense → Tucker 截斷 → 微調」，驗證 §4.4 的主導性 \(\mathcal{L}^{(\text{scratch})}\le\mathcal{L}^{(\text{post-hoc})}\)。
  3. 有效秩驗證： 對學到的 \(G^{(e)}\) 做 SVD，畫奇異值譜，實證 §3 / §4.3 的「尾巴可忽略」前提（這條前提無法事前證明，只能事後量）。
  4. 把界寫成 Proposition： §4.3 的條件式上界明確標為「motivation 而非 guarantee」，並用上一條的譜當作前提的經驗驗證。

9.3 應用場景：可以用在哪裡

核心論點。 凡是「某個軸上有大量相似的權重塊」的結構，都能套這招（沿該軸做 Tucker、共享 core、用低維係數區分）——MoE 的專家軸只是其一。
  • 端側 / 邊緣 LLM 推論（本專案主線）：Apple Silicon、手機、記憶體受限裝置——把 dense-equivalent 容量塞進可負擔的記憶體與頻寬。
  • 專家數受限的 MoE：邊際專家成本 \(=r_1\)，可用極低成本「加專家」換容量；適合 domain-MoE（專家=領域）。
  • 參數高效微調（Tucker-LoRA）：多個 adapter 共享一個 core，只用 \(r_1\) 係數區分任務 → 比獨立 LoRA 更省，天然支援多任務切換。
  • 持續學習 / 多領域：新領域 = 新增一個 \(r_1\) 維係數向量，不膨脹主體，緩解災難性遺忘的容量壓力。
  • MoE 之外的「群組軸」：multi-head attention 的 head 軸、grouped convolution 的 group 軸、per-token routing——同樣可沿群組軸 Tucker 共享。
  • SSM 狀態 / KV 壓縮：把同思路用在 Mamba 狀態或 KV cache 的低秩因子化，攻長序列的記憶體牆。
