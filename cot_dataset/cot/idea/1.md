針對你「強化推理完整性、避免發散」的目標，且限定在 SFT 階段以輕量 Loss 工程處理，以下提供 **3 個直接可用的技術方案**，全都不走 PPO，也超越單純對 `<think>` 加權的思維。你的 JSON 結構很適合直接轉成帶有 cot（推理過程）的訓練序列，重點在於讓模型「不敢隨便跳過推理步驟」或「推理到一半就胡亂輸出答案」。

## 方案一：對 CoT 段落施加熵感知 Focal Loss（MiLe Loss 變體）

### 核心概念

標準 CE Loss 對簡單 token 和困難 token 一視同仁，但推理過程常因「模型對某步過度自信」而發散——一旦推錯一步，後續全盤皆錯。  
**做法**：只在 cot 段落內，改用 **MiLe Loss**（基於預測熵動態加權的 focal loss）。模型輸出某 token 的熵越高（表示越不確定），代表該推理步驟越困難，就給予更高 loss 權重，強迫模型認真學習那些容易出錯的關鍵推導點。

### 公式邏輯

對 cot 範圍內的每個位置 $t$，計算預測分佈的熵 $H(p_t) = -\sum_v p_t(v)\log p_t(v)$，權重 $w_t = \text{softplus}(H(p_t) - \tau)$（$\tau$ 為門檻值），總損失：
$$\mathcal{L}_{\text{cot}} = \sum_{t \in \text{cot}} w_t \cdot \text{CE}(p_t, y_t)$$
其他 token（input、output 段落）仍用普通 CE。這樣在 cot 段落內自動聚焦於模型最不穩定的推理 token，減少隨機猜測導致的發散。

### 實作難度

**低**。只需在 loss function 中判斷 token 位置是否屬於 cot mask，並對那段計算熵加權 CE。PyTorch 約 20 行程式碼，完全可微，無需額外模型。

### 技術來源

- _MiLe Loss: Mitigating the Bias of Learning Difficulties in Generative Language Models_ (2024, OpenReview)  
  → 雖用於通用文本，但直接套用到推理段落效果極佳。

## 方案二：Step-DPO — 用偏好最佳化教模型「不可發散」

### 核心概念

PPO 太慢的主因是需要在線生成 rollout 並用 Reward Model 打分。**Step-DPO**（步驟級直接偏好最佳化）是一種離線 DPO 變體，專門為長鏈推理設計：它把一串正確推理步驟視為 preferred，把「截斷、跳步或錯誤推論」視為 rejected，直接以偏好對比損失訓練模型，完全不需額外 reward model 或生成 rollout。  
對於你的數據，可以 **自動構造 rejected 樣本**：例如把正確 cot 隨機刪除一個步驟、打亂步驟順序、或直接拿沒有 cot 的輸出當作 rejected。這樣模型就會學到「有完整推理的答案比亂猜更受偏好」。

### 公式邏輯

對每個偏好對 $(y_w, y_l)$（$y_w$=正確 cot+輸出，$y_l$=破壞後的版本），使用 token-level DPO（如 TAB-PO 的加權版），重點對 cot 內的重要結構 token（步驟分隔符、邏輯連詞）加重權重：
$$\mathcal{L}_{\text{step-DPO}} = -\sum_t \alpha_t \cdot \log\sigma\left(\beta(\log\frac{\pi_\theta(y_{w,t})}{\pi_{\text{ref}}(y_{w,t})} - \log\frac{\pi_\theta(y_{l,t})}{\pi_{\text{ref}}(y_{l,t})})\right)$$
$\alpha_t$ 在 cot 步驟關鍵詞（如 “Step 1:”、“**所以**”）處給 1.5，其他為 1.0。訓練只需一次前向計算一對，比 PPO 快 10 倍以上。

### 實作難度

**中**。可使用 HuggingFace TRL 的 `DPOTrainer`，繼承後改寫 `_get_batch_logps` 並加入 token 權重。生成 rejected 樣本的腳本約 30 行。核心是偏好對的設計。

### 技術來源

- _Step-DPO: Step-wise Preference Optimization for Long-chain Reasoning of LLMs_ (arXiv:2406.18629, 2024)
- _TAB-PO: Preference Optimization with a Token-Level Adaptive Barrier_ (2025) → 提供 token 加權 DPO 實作細節。

## 方案三：EOS 長度懲罰正則化 — 不讓模型提早收工

### 核心概念

模型經常在 cot 只寫了兩三句就急著輸出答案（early stopping），導致推理不完整。你可以在 loss 層級直接 **懲罰過早出現的 EOS token**，強迫模型產生足夠長的推理過程。這不需要外部監督，只需設定一個「預期最小 cot 長度」$L_{\min}$，當模型實際 cot 長度短於此時，對 EOS 位置的 logit 進行抑制。

### 公式邏輯

訓練時，模型生成的序列會在 ground-truth 序列最後加上 EOS。若 cot 結束位置 $t_{\text{cot-end}}$ 小於 $L_{\min}$，則額外增加一個懲罰項：
$$\mathcal{L}_{\text{EOS}} = -\lambda \cdot \log(1 - p_{\text{EOS}}^{(t_{\text{cot-end}})})$$
$p_{\text{EOS}}^{(t)}$ 為該位置的 EOS 機率。這會提高模型在推理中途生成 EOS 的 loss，從而推遲停止。也可改用 soft 版本：對整個 cot 段落內的 EOS 預測機率施加指數衰減加權。

### 實作難度

**低**。可直接在原始模型 forward 中取得 logits，找出 cot 結尾位置，計算上述懲罰後加回總 loss。約 15 行程式碼。

### 技術來源

- 此為文本生成長度控制的常見手法，類似 _Length-Control for Text Generation_ 概念，實作簡單無需外部論文，但可參考 _GSum: A General Framework for Guided Neural Abstractive Summarization_ 中的長度引導訓練章節。

## 綜合建議

你可以將方案一與方案三結合作為 **首輪快速嘗試**（純 loss 修改，不需重構數據），再將方案二（Step-DPO）作為 **第二階段強化**（需準備 rejected 樣本，但效果更根本）。這三招都跳脫了單純對 `<think>` 標籤加權的框架，能在幾小時內完成實驗，完全符合你「不增加數據、不做 PPO」的約束。
