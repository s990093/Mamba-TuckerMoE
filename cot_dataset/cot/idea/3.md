大型語言模型在複雜結構與程式碼生成中之損失函數優化研究報告
複雜結構輸出的技術背景與監督式微調之挑戰
在當前人工智慧的實際應用場景中，大型語言模型（Large Language Models, LLMs）的部署逐漸從單純的自然語言對話，轉向高度結構化的數據生成任務。這類任務通常要求模型輸出符合嚴格語法規範的程式碼，或是具備多層次嵌套關係的 JSON 負載。以具體的多步推理與寫作潤飾場景為例，系統通常要求模型將使用者的問題解析為多個預定義的欄位，如下列標準的訓練數據範例：

JSON
{
"id": "gen_0009",
"category": "writing_assist",
"input": "Can you make this sentence sound less aggressive? 'You need to send me the report by Friday.'",
"cot": "Step 1: **Classify request** — Tone adjustment for workplace communication from directive to collaborative.\nStep 2: **Identify aggression triggers** — 'You need to' is a command, not a request.\nStep 3: **Rebuild sentence** — Replace obligation language with a shared-goal framing.",
"output": "The current phrasing issues an **unilateral imperative**. Replace with a collaborative deadline statement.\n\nRevised: **'Could you share the report by Friday? It will help us finalize the presentation on time.'**\n\nThis repositions the request as a **shared objective** rather than a demand."
}
在這類嚴苛的應用情境下，開發者通常會將 input、cot 與 output 拼接為單一序列，並設置 Mask 僅對 cot 和 output 計算損失。然而，若模型在生成 cot（推理鏈）時中途發散、提前跳轉至 output，或是遺漏了單一的雙引號與大括號，皆會導致推理不完整或下游解析程式崩潰。

歷史上，產業界主要依賴標準的監督式微調（Supervised Fine-Tuning, SFT）來使預訓練模型適應特定的下游結構化任務 。然而，近兩年的研究顯示，標準的監督式微調在處理確定性結構邊界與長推理鏈時存在根本性的數學缺陷 。當開發者面臨運算資源受限，且「禁止依賴大規模數據擴增、過採樣，且禁止使用重型 PPO/RLHF 等在線強化學習」的嚴格限制時，傳統的交叉熵（Cross-Entropy, CE）損失函數便成為了最大的技術瓶頸 。

本研究報告旨在深入剖析過去兩年內，學術界與開源社群針對 LLM 在 SFT 階段所進行的輕量級損失函數與權重修改技術。本報告篩選出四個完全符合標準 SFT 流程、無需大幅改動模型架構、且能在 PyTorch / Hugging Face 框架下快速實作的代表性方案。

結論
在要求 LLM 輸出高度結構化且具備長推理鏈的 SFT 任務中，若受限於運算資源並排除重型 RLHF，解決方案必須精確收斂於損失函數的輕量級底層工程。

本報告證實：動態詞元加權與焦點損失（如 ResT 演算法）能透過提升推理詞元的權重，有效防止模型對簡單詞元的過擬合；無參考模型的偏好優化（如 ORPO/SimPO）提供了一條極低工程複雜度的捷徑，能在標準 SFT 的耗時內，透過對比損失徹底消除提早結束或發散的軌跡；而信心對齊邊界損失則能從數學層面鎖定 cot 與 output 的嚴格過渡邊界。開發者可依據專案時程，優先選擇 ORPO 或焦點加權方案進行數小時內的快速實驗驗證。
